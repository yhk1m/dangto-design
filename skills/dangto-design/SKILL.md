# 당토 디자인 (dangto-design)

당근과 토스의 공개 디자인 시스템과 글을 중심으로, 관리 화면과 브랜드 표현은 LINE, 원티드, 채널톡, 쏘카, 뱅크샐러드, 배민, 29CM, 카카오페이의 공개 자료로 보탰다. 여러 곳에서 겹치는 규칙만 모았다. 각 회사의 공식 자료가 아니라 공개 자료를 읽고 정리한 개인 스킬이다. 목표는 "배우지 않아도 바로 쓰는 화면"이다. 화려함이 아니라 정보의 위계와 덜어냄으로 완성도를 만든다.

**쓰는 곳:** 앱 화면, 웹 도구, 관리자 화면, 설정, 입력 양식, 목록, 상태 화면
**쓰지 않는 곳:** 랜딩 페이지, 포트폴리오, 슬라이드 (랜딩 페이지용 디자인 스킬이 따로 맡는다)

## 0. 시작 절차

코드를 쓰기 전에 아래 세 가지를 정한다. 사용자가 이미 말했거나 프로젝트에 정해져 있으면 묻지 않고 그대로 쓴다.

1. **테마색 1~3개.** `references/accent.md`의 프리셋 6개 중 고르기, 색 값 직접 받기, 프로젝트에 있는 브랜드색 쓰기 중 하나. 주색은 꼭 있어야 하고 보조색, 셋째 색은 선택.
2. **밀도 다이얼:** 묻지 않고 화면 종류로 정한다. 학생, 고객, 일반 사용자가 쓰는 화면은 `편안`, 교사, 운영자, 관리자가 쓰는 관리 화면과 표는 `촘촘`. 한 프로젝트 안에서 화면마다 다르게 쓴다. 사용자가 따로 말하면 그 말을 따른다.
3. **개성 다이얼:** `담백`이 기본이다. 사용자가 브랜드, 개성, 홍보를 말할 때만 `브랜드`로 바꾼다.

묻지 못하는 상황이면 기본값(주색은 프리셋 "숲", 화면 종류에 맞는 밀도, 담백)으로 시작하고 무엇을 골랐는지 결과 보고에 적는다.

4. **부품을 어디서 가져올지 정한다.** 버튼, 바텀시트, 스위치 같은 부품은 처음부터 그리지 말고 `references/components.md`를 읽고 고른다.
   - 앱인토스(토스 안 미니앱): TDS Mobile
   - React 프로젝트: SEED React (당근, Apache-2.0). 브랜드색은 반드시 고른 테마색으로 바꾼다
   - React가 아닌 프로젝트: 라이브러리 없이 tokens.css와 patterns.md로 만들고, 크기와 상태는 SEED 문서를 따른다

그다음 `assets/tokens.css`를 프로젝트에 복사해서 쓴다. 색, 글자, 간격, 모서리, 그림자, 움직임 값이 모두 들어 있고 `--accent` 값 하나만 바꾸면 나머지 강조 계열 색이 따라 바뀐다.

## 1. 원칙 6개

1. **배우지 않아도 바로 이해된다.** 설명이 필요하면 설계가 잘못된 것이다. 3초 안에 화면 목적이 보여야 한다.
2. **한 화면에 목표 하나, 주요 버튼 하나.** 채운 강조색 버튼은 화면마다 하나만 둔다.
3. **덜어낸다.** 여백으로 나눌 수 있으면 선을 긋지 않는다. 기능, 장식, 문구를 더하는 건 마지막 수단이다.
4. **결과를 예측할 수 있게 한다.** 누르기 전에 결과, 비용, 조건을 보여 준다. 되돌릴 수 없는 행동은 확인을 받거나 되돌리기를 준다.
5. **사용자 머릿속 개념대로 묶는다.** 회사 조직, 데이터베이스 표, 상품 구분대로 나누지 않는다.
6. **빈 화면, 오류, 로딩도 기본 화면처럼 설계한다.** 행복한 경로만 그리고 끝내지 않는다.

## 2. 핵심 시각 규칙

자세한 값은 `references/tokens.md`에 있다. 여기서는 어기기 쉬운 것만 적는다.

**색**
- 회색은 남색 기운이 살짝 도는 10단계. 가장 진한 글자도 순수 검정(#000)이 아니다.
- 바탕은 연한 회색, 그 위에 흰 면. 흰 면끼리는 그림자 대신 바탕색 차이로 나눈다.
- 강조색은 주요 행동, 선택 상태, 진행 막대에만. 링크마다, 아이콘마다 칠하지 않는다.
- 글자 위계는 회색 3~4단계(진함, 보통, 흐림, 비활성)로 만든다. 크기를 키우기 전에 회색 단계부터 쓴다.
- 상태색은 4개(성공, 주의, 위험, 정보). 빨강은 되돌릴 수 없는 행동과 실제 오류에만.
- 보조색은 브랜드 영역(머리 띠, 로고)과 차트에, 셋째 색은 배지, 일러스트, 홍보 띠에만 쓴다. **둘 다 버튼과 링크에는 쓰지 않는다.**

**다크 모드**
- 라이트를 뒤집지 않는다. 바탕은 #121418 안팎의 아주 어두운 회색이고, 위로 올라온 면일수록 밝게 한다.
- 그림자 대신 면의 밝기 차이로 높이를 나타낸다.
- 강조색은 밝게 올리고, 그 위 글자색은 대비를 다시 계산한다(밝은 강조색 위에는 어두운 글자).

**글자**
- Pretendard 또는 시스템 기본 글꼴. 굵기는 400, 500, 600, 700 중 쓰고, 촘촘 모드는 2종(400, 600)만.
- 본문: 편안 16px, 촘촘 13~14px. 어떤 경우에도 12px 아래로 내리지 않는다.
- 큰 제목은 자간을 음수로(-0.4px 안팎), 작은 글씨는 0.
- 숫자가 줄 맞춰 바뀌는 곳(금액, 시각, 표)은 `font-variant-numeric: tabular-nums`.
- 크기는 rem으로 지정해서 사용자 글자 크기 설정을 따른다.

**간격, 모서리, 그림자, 움직임**
- 간격은 4px 단위. 화면 좌우 여백은 모바일 16~20px.
- 모서리는 작은 것일수록 작게: 배지 4, 버튼 8~12, 카드 12~16, 시트와 대화상자 16~24. 브랜드 개성에서 0을 고르면 전부 0.
- 그림자는 떠 있는 것(시트, 메뉴, 토스트)에만, 투명도 0.12 이하.
- 반응은 150ms, 전환 250ms, 큰 전환 400ms 이하. 들어올 때 감속 곡선. `prefers-reduced-motion`을 따른다. 장식용 애니메이션은 넣지 않는다.

## 3. 다이얼 두 개

| | 편안 (기본) | 촘촘 |
|---|---|---|
| 대상 | 사용자 앱, 신청, 설정 | 관리자 화면, 표, 상담 도구 |
| 본문 | 16px | 13~14px |
| 목록 한 줄 | 56px 안팎, 두 줄(제목+보조 글) | 36~40px, 한 줄, 표 |
| 버튼 높이 | 48~56px | 32~36px |
| 굵기 | 최대 4종 | 2종 |

| | 담백 (기본) | 브랜드 |
|---|---|---|
| 글꼴 | 본문 글꼴 하나 | 제목에만 쓰는 서체 하나 추가 |
| 모서리 | 기본 단계 | 0 또는 크게 중 하나로 성격을 준다 |
| 보조색, 셋째 색 | 거의 안 씀 | 머리 띠, 배지, 홍보 띠 |
| 유머와 말맛 | 없음 | 홍보 영역에만. 기능 화면 문구는 그대로 담백 |

다이얼은 겉모양만 바꾼다. 원칙, 문구 규칙, 금지 목록은 어느 조합에서도 같다.

## 4. 화면 패턴

`references/patterns.md`에 목록 줄, 카드 묶음, 버튼 위계, 하단 고정 버튼, 대화상자, 토스트, 빈 화면, 오류, 로딩, 입력 양식, 분할 관리 화면 규칙이 있다. 화면을 만들기 전에 해당 패턴을 읽는다.

가장 자주 쓰는 셋:
- **목록 한 줄:** 왼쪽 아이콘(선택) + 가운데 제목과 회색 보조 글 + 오른쪽 값이나 화살표. 줄 사이 선은 없거나 들여쓴 선. 줄 전체가 눌린다.
- **버튼 위계:** 채움(주색) → 연한 주색 바탕 → 회색 바탕 → 글자만. 모바일 주요 행동은 하단 고정 버튼.
- **관리 화면:** 숫자 카드를 늘어놓지 말고, 할 일 목록과 선택한 항목의 상세를 나란히 둔다(분할 화면). 요약은 한 문장과 막대 하나. 칸은 두 개(목록, 상세)까지. 셋째 정보는 다른 탭으로 뺀다.

## 5. 문구

`references/writing.md`에 바꿔 쓰기 예시가 있다. 화면 문구를 쓰기 전에 읽는다.

- 해요체. "되어요"는 "돼요". 과한 존칭("~하시겠어요?", 계시다, 여쭈다)은 쓰지 않는다.
- 능동문, 긍정문. 할 수 없는 것보다 할 수 있는 것을 말한다.
- 전문 용어, 한자어, 은어, 축약어 대신 일상어. 고등학생이 바로 읽을 수 있게.
- 버튼은 기능 이름 대신 누른 결과("확인" 대신 "5명에게 알림 보내기"). 1~3단어, 마침표 없음.
- 대화상자의 닫는 버튼은 "취소" 대신 "닫기".
- 오류 문구는 무엇이 일어났는지와 어떻게 하면 되는지를 함께. 기술 용어(500, null, 네트워크 예외) 금지.
- 숫자는 아라비아 숫자. 느낌표는 아낀다.
- 보이는 글에 가운데 점(·)과 긴 대시(—)를 쓰지 않는다. 쉼표나 문장 나누기로 바꾼다.
- 옵션 라벨에 "추천"을 쓸 때 "추시"로 잘못 쓰지 않았는지 확인한다.

## 6. 금지 목록

**전체**
- UI에 이모지. 아이콘은 선 SVG(굵기 1.5~2px, 끝 둥글게)로.
- 순수 검정 글자, 순수 검정 다크 바탕
- 한 화면에 채운 강조색 버튼 여러 개, 강조색 여러 개
- 여백으로 충분한데 넣은 구분선과 테두리 상자
- 진한 그림자, 강한 그라디언트, 빛나는 효과, 유리 효과, 파티클 같은 장식
- 들어오자마자 뜨는 팝업, 겹쳐 뜨는 팝업, 거절할 수 없는 선택
- 미리 깔아 두는 경고 문구, 오류가 아닌데 쓰는 느낌표 아이콘
- 즉시 끝나는 작업의 로더, 스켈레톤과 스피너를 같이 쓰기
- 누를 수 없는데 버튼처럼 보이는 것
- 선택 표시용 왼쪽 강조 줄을 둥글게 그리기 (모서리 없는 일자 막대로)

**관리 화면에서 피할 AI 티**
- 같은 크기 숫자 카드 4개를 맨 위에 늘어놓기. 그 화면에서 할 일 하나를 정하고 숫자는 한 문장 요약과 막대 하나로.
- 모든 줄 끝에 강조색 "보기" 링크. 줄 전체를 누르게 하고, 행동 버튼은 선택한 항목에만.
- 모든 줄에 색 태그. 처리할 것만 색, 나머지는 회색 글자로, 끝난 것은 접기.
- 의미 없는 로고 네모, 이름 첫 글자 동그라미 아바타. 글자 로고로 충분하다.
- 제목 위 작은 영문 대문자 설명 글(eyebrow) 습관.
- 몇십 줄밖에 안 되는데 쪽 나누기.
- 할 일이 남았는데 마무리 버튼("공개하기", "완료")을 강조하기. 지금 상태에 맞는 다음 행동을 강조한다.
- 한 화면을 세 칸 이상으로 나눠 모든 정보를 한꺼번에 보여 주기. 칸은 두 개까지.
- 왼쪽 메뉴, 숫자 카드, 검색창, 표 순서의 틀을 습관처럼 쓰기. 화면의 할 일이 구조에 드러나야 한다.

## 7. 완성 전 점검표

결과를 보고하기 전에 하나씩 확인하고, 어긴 것은 고친 뒤 보고한다.

- [ ] 3초 안에 화면 목적이 보이는가 (제목이나 첫 문장이 그 화면의 할 일을 말하는가)
- [ ] 채운 강조색 버튼이 화면마다 하나뿐인가, 강조색을 쓴 곳이 주요 행동과 선택 상태뿐인가
- [ ] 여백으로 충분한 곳에 선이나 상자를 넣지 않았는가
- [ ] 순수 검정 글자, 순수 검정 다크 바탕이 없는가
- [ ] 빈 화면, 오류, 로딩 상태를 만들었는가 (실제 앱이면 만들고, 한 장짜리 시안이면 각 상태에서 무엇을 보여 줄지 보고에 한 줄씩 적는다)
- [ ] 버튼 라벨이 누른 결과를 말하는가, 문구가 해요체인가, 가운데 점과 긴 대시가 없는가
- [ ] 다크 모드가 있고, 글자 대비 4.5:1, 터치 영역 44px을 지켰는가
- [ ] 이모지가 없고 아이콘이 모두 선 SVG인가
- [ ] 관리 화면이면 위 "AI 티" 9가지에 걸리지 않는가

# 화면 패턴

## 목록 한 줄 (가장 많이 쓰는 단위)

```
[아이콘]  제목                       값 또는 상태  >
          회색 보조 글
```
- 왼쪽 아이콘은 있어도 되고 없어도 된다. 있으면 24px 선 아이콘이나 40px 원 안의 아이콘.
- 가운데: 제목(`--fs-body-lg`, 600) + 보조 글(`--fs-small`, `--text-muted`). 보조 글은 한 줄.
- 오른쪽: 값(숫자는 tabular-nums), 짧은 상태 글자, 화살표(`--icon-muted`) 중 하나나 둘.
- 줄 사이 선은 없거나, 글자 시작점부터 그은 들여쓴 선. (토스 ListRow)
- 줄 전체가 눌린다. 줄 안에 따로 "보기" 링크를 넣지 않는다.
- 줄 위아래 여백은 8, 12(기본), 16, 24px 네 단계, 좌우는 20이나 24px. 한 목록 안에서는 한 단계로 맞춘다. 묶음 사이를 더 벌리고 싶으면 줄 여백을 키우지 말고 묶음 간격을 준다.
- 왼쪽 아이콘과 그림은 정해진 크기만 쓴다: 선 아이콘 24px, 원 안 아이콘 40px, 사진 네모 52px.
- 상태 글자는 처리가 필요한 것만 색(주의, 위험)을 쓰고 나머지는 회색. 상태색은 흰 바탕과 회색 바탕(선택한 줄) 모두에서 4.5:1을 넘는 값이라 그대로 쓴다.

## 켜고 끄기 (설정 화면)

- 목록 한 줄의 오른쪽에 스위치. 줄 전체를 눌러도 바뀐다.
- 켜짐은 주색 채움 + 흰 손잡이, 꺼짐은 `--gray-300` 바탕. 스위치는 선택 상태라서 여러 개여도 강조색 규칙 위반이 아니다.
- 주색이 밝으면(개나리) 흰 손잡이 안에 진한 체크를 넣어 켜짐을 색 말고도 알 수 있게 한다.
- 먹 다크처럼 주색 자체가 흰색에 가까우면 손잡이를 `var(--on-accent)`로 칠한다(흰 손잡이가 묻힌다).
- 켜면 바로 적용한다. "저장" 버튼을 따로 두지 않는다.
- 스위치에 딸린 설정(받는 시각 등)은 바로 아래 줄에 두고, 꺼지면 흐리게 한다.
- 값을 바꾸는 줄은 오른쪽에 회색 값 + 화살표. 값을 주색 글자로 칠하지 않는다.

## 카드 묶음

- 회색 바탕(`--bg`) 위 흰 면(`--surface`), 모서리 `--r-card`, 그림자 없음.
- 카드 위에 작은 묶음 제목(`--fs-small`, 600, `--text-muted`)을 둔다. 카드 안에 제목을 또 넣지 않는다.
- 카드 안 목록 줄 사이에는 선 대신 여백.
- 같은 크기 카드를 격자로 늘어놓는 것은 사진이나 상품처럼 같은 종류일 때만.

## 버튼 위계

| 단계 | 모양 | 쓰는 곳 |
|---|---|---|
| 1 채움 | `--accent` 바탕, `--on-accent` 글자 | 화면의 주요 행동 하나 |
| 2 연한 채움 | `--accent-weak` 바탕, `--accent-text` 글자 | 같이 자주 쓰는 둘째 행동 |
| 3 회색 | `--fill-subtle` 바탕, `--text-strong` 글자 | 닫기, 나중에, 보조 행동 |
| 4 글자만 | 바탕 없음, `--text` 글자 | 더 보기, 덜 중요한 링크 |
| 위험 | `--critical` 바탕 또는 글자 | 삭제처럼 되돌릴 수 없는 행동만 |

- 두 버튼을 나란히 둘 때 주요 행동이 오른쪽(엄지 자리). 닫기, 나중에가 왼쪽.
- 로딩 중에는 글자 대신 작은 점 3개나 스피너를 넣되 버튼 너비를 그대로 두고, 다시 누르지 못하게 한다. `aria-busy="true"`를 단다.
- 아이콘만 있는 버튼에는 `aria-label`. 라벨에 "버튼", "스위치", "체크박스", "탭", "켜짐/꺼짐" 같은 부품 이름과 상태를 넣지 않는다(화면 읽기 프로그램이 따로 읽어 준다).
- 필수 입력 전 비활성 버튼은 왜 못 누르는지 근처에 짧게 알려 준다("이름을 적으면 다음으로 갈 수 있어요").
- 라벨은 결과를 말한다. 아래 문구 문서 참고.

## 하단 고정 버튼 (모바일)

- 화면 아래 고정, 좌우 여백 `--page-x`, 높이 `--btn-h`, 채움 버튼 하나가 기본.
- 둘이면 좌우로 나누고 왼쪽은 회색. 셋 이상 두지 않는다.
- 키보드가 올라오면 키보드 바로 위로 붙인다.
- 아래 여백은 `max(env(safe-area-inset-bottom), 20px)`. 홈 막대에 가리지 않고, 홈 막대가 없는 기기에서도 바닥에 붙지 않는다. 본문 맨 아래도 버튼 높이만큼 비워 둔다.
- 본문이 버튼 뒤로 지나갈 때는 버튼 영역 위쪽을 바탕색으로 부드럽게 흐리게 해서 글자와 겹쳐 보이지 않게 한다.
- 버튼 위아래에 짧은 안내 한 줄(약관 동의, 비용)을 붙일 수 있다. 두 줄을 넘기지 않는다.
- 아래 탭 막대가 있는 화면에는 두지 않는다. 하단 버튼이 필요한 화면(상세, 신청 흐름)에서는 탭 막대를 숨긴다.
- 태블릿에서는 화면 폭 전체로 늘이지 않고 본문 칸 폭(`--content-max`)이나 그 버튼이 속한 칸 폭에 맞춘다. `references/responsive.md` 참고.
- 버튼 위에 과장된 문구("지금 안 하면 손해!")를 붙이지 않는다. 필요하면 조건이나 비용을 한 줄로.

## 대화상자

- 즉시 주의가 필요하거나 되돌릴 수 없는 행동일 때만 쓴다. 정보 전달은 대화상자 대신 화면 안 문구나 토스트.
- 제목(무엇이 일어나는지) + 한두 줄 설명(결과, 되돌릴 수 있는지) + 버튼 2개.
- 버튼: 왼쪽 "닫기"(회색), 오른쪽 결과 라벨("3개 지우기"). "확인/취소" 짝을 쓰지 않는다.
- 한 번에 하나. 대화상자 위에 대화상자를 띄우지 않는다.
- 알리기만 할 때는 버튼 하나("알겠어요"), 고르게 할 때만 버튼 두 개.
- 버튼 라벨이 길어 한 줄에 둘이 안 들어가면 위아래로 쌓고 각각 폭 전체로. 주요 행동이 위.
- 제목이 길면 줄을 바꾸고, 설명이 길면 대화상자 안에서 스크롤한다. 버튼은 늘 보이게.
- 바깥(뒤 막)을 누르거나 뒤로 가기를 누르면 닫힌다. 닫으면 안 되는 경우(입력 중인 내용이 사라짐)에는 닫지 않고 살짝 흔들어 알린다.
- 열려 있는 동안 초점은 대화상자 안에서만 돈다. 닫으면 연 단추로 초점을 돌려준다(`<dialog>`의 `showModal()`이 해 준다).
- 휴대폰은 바텀시트로 대신할 수 있다. 시트는 들어오자마자 띄우지 않는다. 태블릿(744px 이상)에서는 바텀시트 대신 가운데 대화상자(최대 폭 32rem).

## 바텀시트

- 제목 한 줄 + 짧은 설명 + 내용 + 아래 버튼(하나나 둘). 내용과 버튼 사이 34px 안팎.
- 바깥을 누르거나 뒤로 가기를 누르면 닫힌다. 이 동작을 막지 않는다.
- 위로 끌면 화면 전체로 펼칠 수 있고, 아래로 끌면 닫힌다. 끌기 말고도 닫는 방법(바깥 누르기, 닫기 버튼)이 있어야 한다.
- 입력 칸이 있는 시트는 키보드 위로 올라온다.
- 높이는 내용만큼, 최대 화면 높이의 90% 안쪽. 넘치면 시트 안에서 스크롤한다. 글자를 크게 키운 사용자(160% 이상)에게는 제목도 함께 스크롤되게 해서 내용이 가려지지 않게 한다.
- 하나만 고르는 목록 시트는 고른 항목에 체크를 보이고, 고르면 바로 닫는다.
- 뒤로 가기를 눌렀을 때 시트를 띄워 붙잡지 않는다(금지 목록).

## 메뉴 (탭 막대, 햄버거)

휴대폰의 주요 목적지 2~5개는 아래 탭 막대, 햄버거와 서랍은 메뉴가 6개 이상인 웹 도구와 관리 화면에만 쓴다. 고르는 기준, 머리 막대, 탭 막대, 서랍의 크기와 동작, 태블릿에서 바뀌는 모양은 `references/responsive.md` 3절에 있다.

## 토스트, 스낵바

- 한 번에 하나, 1~2줄, 3초 뒤 사라짐. 버튼이 있으면 누를 시간을 주려고 5초.
- 토스트: 버튼 없음, "저장했어요"처럼 끝난 일 알림. 앞에 작은 아이콘(24px) 하나까지.
- 스낵바: 버튼 하나("되돌리기")까지. 화면 아래에만 둔다.
- 하단 고정 버튼이 있는 화면에서는 그 위에 띄운다. 버튼을 가리지 않는다.
- 끌어서 치울 수 있다. `aria-live="polite"`(급한 것만 `assertive`)로 화면 읽기 프로그램이 읽게 한다.
- 오류나 꼭 읽어야 할 정보는 토스트로 보내지 않는다(사라지면 못 본다).

## 탭, 세그먼트

- 화면 안 탭: 고정 폭이면 4개까지. 더 많으면 글자 폭에 맞춘 가로 스크롤 탭으로 바꾼다.
- 고른 탭은 진한 글자와 아래 막대, 나머지는 회색 글자. `role="tablist"`, `role="tab"`, `aria-selected`.
- 새 소식이 있는 탭은 이름 오른쪽 위에 작은 점 하나. 숫자 배지를 남발하지 않는다.
- 세그먼트: 서로 배타적인 보기 2~5개를 바꿀 때(목록/지도, 주/월). 라디오와 같은 역할이라 `role="radiogroup"`과 `role="radio"`. 내용을 바꾸는 탭과 섞어 쓰지 않는다.

## 빈 화면

```
       (선 아이콘 하나, 64~72px 원 안)
       무엇이 없는지 한 문장
   왜 비었는지 또는 언제 채워지는지 한 줄
          [다음 행동 버튼 하나]
```
- 처음 쓰는 사람의 빈 화면과 검색 결과 없음은 문구가 다르다. 검색 결과 없음은 검색어를 바꾸는 방법을 알려 준다.
- 버튼은 하나. 연한 채움이나 채움.
- 큰 일러스트, 이모지, 귀여운 말장난은 넣지 않는다(브랜드 개성의 홍보 영역은 예외).

## 오류

- 무엇이 안 됐는지 + 어떻게 하면 되는지. 기술 용어, 오류 번호를 본문에 넣지 않는다(필요하면 작은 글자로 맨 아래).
- 입력 오류는 입력 칸 바로 아래에, 칸 테두리와 글자를 `--critical`로. 입력하는 도중이 아니라 칸을 떠날 때 알려 준다.
- 화면 전체 오류는 빈 화면과 같은 틀 + "다시 시도하기" 버튼.
- 느낌표 아이콘은 실제 오류에만.

## 로딩

| 기다림 | 보여 줄 것 |
|---|---|
| 1초 미만 | 아무것도 없음 |
| 1~4초 | 모양을 예상할 수 있으면 스켈레톤, 아니면 작은 스피너 |
| 4~10초 | 진행 막대 |
| 10초 이상 | 진행률과 남은 시간, 다른 일을 해도 된다는 안내 |
| 1분 이상 | 뒤에서 진행, 끝나면 알림, 취소 버튼 |

- 스켈레톤과 스피너를 같이 쓰지 않는다. 스켈레톤은 실제 화면과 같은 모양.
- 내용이 고정된 화면(설정 목록 등)에는 스켈레톤을 쓰지 않는다.

## 입력 양식

- 한 화면에 질문 하나(모바일 신청 흐름). 큰 질문형 제목("어느 날 다녀올까요?") + 짧은 도움말.
- 단계가 있으면 위에 얇은 진행 막대와 "2 / 3".
- 라벨은 칸 위에. 자리표시 글자(placeholder)를 라벨 대신 쓰지 않는다.
- 아는 값은 미리 채운다. 고를 수 있는 건 고르게 한다.
- 단위와 기호는 칸 안 앞뒤에 둔다("원", "kg"). 숫자는 입력하는 대로 쉼표를 넣어 보여 준다.
- 글자를 지우는 칸(검색, 이름)에는 내용이 있을 때만 지우기 버튼. 비밀번호 칸에는 보이기/숨기기 버튼.
- 생년월일, 전화번호처럼 정해진 길이를 나눠 받는 칸은 앞 칸을 다 채우면 다음 칸으로 초점을 옮긴다.
- 긴 글 칸은 처음에 3~4줄 높이, 내용이 늘면 따라 늘어난다.
- 선택지 카드: 고른 것은 `--accent-weak` 바탕 + 주색 테두리 1.5px + 채운 체크. 못 고르는 것은 흐리게 + 이유.
- 마지막 확인 화면에서 입력한 내용을 다시 보여 주고 고칠 수 있게.

## 관리 화면 (촘촘)

**틀: 할 일 목록 + 상세 분할**
```
[글자 로고]  탭  탭  탭                                     이름
────────────────────────────────────────────────────────────
제목  한 문장 요약("확인할 신청이 6개 있어요")      막대 하나
────────────────────────────────────────────────────────────
확인할 것 (6)          │  선택한 항목 상세
 줄                    │   정보 2열 표
 줄  (선택: 회색 바탕   │   메모
     + 왼쪽 일자 막대)  │
 승인한 12개 ▸ (접힘)   │  [회색 버튼]  [채움 버튼 하나]
```
- 칸은 두 개(목록, 상세)까지. 예약, 최근 기록 같은 셋째 정보는 탭으로 나눈다.
- 숫자 카드 4개 대신 한 문장 + 막대 하나. 막대는 "오늘 할 일이 얼마나 끝났는지"(예: 연락한 연체 8/14)를 보여 준다. 할 일 진행이 없으면 막대를 빼도 된다.
- 목록 줄은 누르면 오른쪽에 상세. 행동 버튼은 상세 아래에만.
- 끝난 항목은 접는다. 수십 줄이면 쪽을 나누지 않는다.
- 표가 필요하면: 머리 12px 회색, 줄 높이 36~40px, 줄 사이 옅은 선, 숫자 오른쪽 정렬, 처리할 칸만 색.
- 필터는 칩 2~4개("확인할 것", "전체"). 고른 칩은 회색 바탕.
- 선택한 줄의 왼쪽 표시 막대는 모서리 없는 일자, 3px.

## 드롭다운(선택 상자), 메뉴, 스크롤바

화면 본문만 테마를 따르고 브라우저가 그리는 부품은 기본 모양(흰 바탕, 회색 스크롤바)으로 남는 일이 많다. 특히 다크 모드에서 펼친 목록과 스크롤바가 하얗게 튀어 보인다. 아래를 모두 지킨다.

**공통 바탕 (빠뜨리면 안 됨)**
- `<head>`에 `<meta name="color-scheme" content="light dark">`와 `theme-color` 두 줄을 넣는다. CSS를 읽기 전의 첫 화면, 스크롤바, 날짜 선택 창, 휴대폰 주소창이 테마를 따른다.
- 다크 모드를 강제하는 요소(`[data-theme="dark"]`)에는 `color-scheme: dark`가 함께 있어야 한다. `tokens.css`에 들어 있으니 지우지 않는다.
- `tokens.css`의 "브라우저 기본 부품" 블록을 지우지 않는다. 스크롤바, 선택 상자, 체크와 라디오, 슬라이더, 자동 완성 바탕, 글자 선택 색, 대화상자 뒤 막이 여기서 맞춰진다.

**선택 상자 (`<select>`)**
- 고를 것이 2~5개면 선택 상자 대신 세그먼트나 라디오 목록을 쓴다. 다 보이는 편이 빠르다.
- 6개 이상이면 기본 `<select>`를 쓴다. 휴대폰에서는 기기 고유의 선택 창이 뜨는 편이 쓰기 쉽다. 화살표는 `tokens.css`가 선 아이콘으로 바꾼다.
- 펼친 목록의 모양은 `tokens.css`가 두 단계로 맞춘다.
  1. 모든 브라우저: 항목의 바탕색과 글자색 (`option` 색)
  2. 펼친 목록을 꾸밀 수 있는 브라우저(Chrome 135 이상): 둥근 모서리, 그림자, 고른 항목 강조, 최대 높이와 안쪽 스크롤 (`appearance: base-select`)
- 항목에 아이콘, 두 줄 설명, 검색이 필요하면 `<select>` 대신 직접 만든 목록(아래 메뉴 규칙)을 쓴다. React면 SEED의 Select Box나 Menu를 쓴다.

**직접 만든 드롭다운, 메뉴, 자동 완성 목록**
- 바탕 `--surface-raised`, 테두리 `--line`, 모서리 `--r-card`, 그림자 `--shadow-2`. 다크에서는 그림자 대신 바탕 밝기로 떠 보이게 한다(토큰이 처리).
- 최대 높이 `min(320px, 60vh)`, 넘치면 목록 안에서 스크롤. 목록이 화면 밖으로 나가면 위로 펼친다.
- 항목 높이: 편안 44px, 촘촘 36px. 마우스를 올린 항목은 `--fill-subtle`, 고른 항목은 `--accent-weak` 바탕에 진한 글자와 체크 아이콘.
- 키보드: 위아래 화살표로 이동, Enter로 고르기, Esc로 닫고 단추로 초점 되돌리기. `role="listbox"`와 `aria-expanded`를 단다.
- 펼치고 닫을 때 150ms 안쪽으로 살짝 내려오며 나타난다. 동작 줄이기 설정이면 바로 나타난다.
- 바깥을 누르면 닫힌다. 메뉴 위에 메뉴를 겹쳐 띄우지 않는다.

**스크롤바**
- 얇은 회색 손잡이에 투명한 길. 색은 `--scroll-thumb` 토큰이라 다크에서 자동으로 밝아진다.
- 스크롤되는 영역은 화면 전체 하나와 꼭 필요한 패널(목록, 상세, 펼친 목록)만. 카드마다 스크롤을 만들지 않는다.
- 내용이 늘었다 줄었다 하는 패널은 `.scroll-stable`(`scrollbar-gutter: stable`)을 붙여 스크롤바가 생길 때 화면이 옆으로 밀리지 않게 한다.
- 가로 스크롤은 표와 가로 카드 목록에만(`.scroll-x`). 넘친다는 것을 알 수 있게 다음 항목이 살짝 보이게 한다. 화면 전체가 옆으로 밀리는 가로 스크롤은 오류다(`references/responsive.md` 2절).

**그 밖의 기본 부품**
- 체크, 라디오, 슬라이더, 진행 막대: `accent-color`로 주색을 따른다. 크기가 작으면 감싼 `label` 전체를 누를 수 있게 한다.
- 날짜, 시간 칸: 선택 창 색은 `color-scheme`이 맞춘다. 직접 그린 달력이 필요하면 SEED Date Picker나 TDS 문서를 참고한다.
- 파일 올리기: `::file-selector-button`을 회색 버튼으로 맞춘다.
- `title` 속성으로 뜨는 말풍선은 꾸밀 수 없으므로 중요한 설명에 쓰지 않는다.

## 그림과 아이콘

- 그림은 꾸미려고 넣지 않고 뜻을 전하려고 넣는다. 그 상황에 맞는 그림만.
- 한 화면에 중심 그림은 하나. 나머지는 작은 아이콘으로. 비슷한 크기의 그림이 여럿이면 눈이 흩어진다.
- 크기는 정보량에 맞춘다. 단순한 그림은 작게(화면 안 아이콘 24~40px), 자세한 그림만 크게.
- 그림이 중요한 정보를 아래로 밀어내 스크롤을 만들면 그림을 줄이거나 옮긴다.
- 아이콘 두 개를 붙여 하나처럼 쓰지 않는다. 한 번에 하나.
- 그림은 상황을 정확히 말해야 한다. 오류가 아니면 느낌표 아이콘을 쓰지 않고, 기다릴 필요가 없으면 로딩 움직임을 넣지 않는다.
- 우는 얼굴, 애원하는 캐릭터처럼 죄책감을 주는 그림은 쓰지 않는다.
- 그림 스타일은 단순하고 깨끗한 디지털 그림. 손그림, 만화풍, 서정적인 그림은 화면과 어긋난다. 파티클, 과한 그라디언트, 뜻 없는 장식 효과는 넣지 않는다.
- 라이트와 다크 양쪽에서 보이도록 중간 밝기 색을 쓰고, 글자나 주요 버튼보다 눈에 띄지 않게 한다.
- 해상도가 충분한 그림(1x, 2x 두 벌, 또는 SVG)을 쓴다.

## 숫자와 차트

- 핵심 숫자 하나는 크게, 나머지는 문장 속에.
- 차트 색은 주색 → 보조색 → 셋째 색 → 회색 순. 비교 대상이 아닌 것은 회색.
- 진행 막대는 높이 4~8px, 둥근 끝, 빈 칸은 `--gray-200`.

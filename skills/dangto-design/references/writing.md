# 화면 문구

## 기본 말투

- 해요체. 친구에게 설명하듯, 그러나 반말은 아니게.
- "되어요"는 "돼요", "하였어요"는 "했어요".
- 과한 존칭을 쓰지 않는다: "~하시겠어요?", "계시다", "여쭈다", "~께".
- 고등학생이 한 번에 읽을 수 있는 말. 한자어와 업계 용어를 일상어로.
- 한 문장에 목적 하나. 소리 내어 읽었을 때 자연스러운지 본다.
- 능동문으로. 사용자나 서비스가 한 일은 "됐어요" 대신 "했어요"("신청됐어요" → "신청했어요"). 쓸데없는 "~었"을 뺀다.
- 명사를 늘어놓지 않는다("본인 확인 진행 필요"). 한자어 명사는 동사로 풀고("본인인지 확인해야 해요"), 풀기 어려우면 "{명사}가 {명사}해서" 꼴로.
- 질문에서 "~시"를 빼면 어색할 때는 묻는 정보를 주어로 바꾼다("직업이 있으신가요?" → "지금 하는 일이 있나요?").

## 원칙의 예외 (이때만 쓴다)

| 원칙 | 예외로 쓰는 때 | 예 |
|---|---|---|
| 능동문 | 서비스가 끝나거나 기간이 끝날 때(주어를 드러내는 편이 분명) | "이벤트가 종료됐어요" (정해진 주기로 매번 끝나는 것에는 쓰지 않는다) |
| 능동문 | 사용자 행동의 결과를 알릴 때(연체, 해지, 적용) | "지금 해지하면 쌓인 포인트가 사라져요" |
| 능동문, 긍정문 | 개인 정보 수집처럼 민감한 흐름에서 안심시킬 때 | "입력한 정보는 다른 곳에 쓰이지 않아요" |
| 존칭 빼기 | 사용자 자신의 상황을 물을 때, 사용자가 스스로 판단해야 할 때, 설문처럼 호의를 부탁할 때 | "최근 3개월 안에 이사하셨나요?" |
| 긍정문 | 정책 때문에 쓸 수 없을 때(이유를 함께), 특정 기능만 쓸 수 없을 때(어느 기능인지) | "만 14세 미만은 송금을 쓸 수 없어요. 보호자 동의가 필요해서예요" |

- 서비스는 쓸 수 있는데 혜택 하나만 못 받는 경우, 부정문을 크게 쓰면 서비스 전체를 못 쓰는 줄 안다. 혜택이 누구를 위한 것인지 긍정문으로 쓴다("이 혜택은 처음 가입한 분께 드려요" 대신 "처음 가입한 사람이 받을 수 있는 혜택이에요").

## 바꿔 쓰기 예시

| 나쁜 예 | 좋은 예 | 이유 |
|---|---|---|
| 확인 | 5명에게 알림 보내기 | 누른 결과를 말한다 |
| 취소 (대화상자) | 닫기 | "취소"는 무엇을 취소하는지 헷갈린다 |
| 제출하시겠습니까? | 신청서를 낼까요? | 과한 존칭, 한자어 |
| 해당 항목이 존재하지 않습니다. | 찾는 신청이 없어요 | 딱딱한 말, 한자어 |
| 비밀번호는 8자 미만일 수 없습니다 | 비밀번호는 8자 이상이어야 해요 | 부정문 대신 긍정문 |
| 네트워크 오류가 발생했습니다 (code 500) | 연결이 잠깐 끊겼어요. 다시 시도해 주세요 | 기술 용어 빼고 해결 방법 |
| 데이터가 없습니다 | 아직 받은 신청이 없어요. 11월 20일까지 받아요 | 무엇이 없는지, 언제 채워지는지 |
| 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다. | 3개를 지울까요? 지운 뒤에는 되돌릴 수 없어요 | 무엇을 몇 개, 결과 |
| 저장되었습니다! | 저장했어요 | 느낌표 아끼기, 능동 |
| 필수 입력 항목입니다 | 이름을 적어 주세요 | 무엇을 해야 하는지 |
| 승인 대기 | 확인 전 | 일상어 |
| 미제출 | 아직 안 냄 | 일상어 (촘촘 화면에서는 "안 냄"도 됨) |
| 처리 완료 | 승인했어요 / 승인 | 상황에 맞게 짧게 |
| 지금 바로 신청하세요! 놓치면 후회! | 11월 20일까지 신청할 수 있어요 | 압박 대신 조건 |
| 서비스 이용을 위해 로그인이 필요합니다 | 로그인하면 신청 내역을 볼 수 있어요 | 할 수 있는 것을 말한다 |

## 버튼 라벨

- 1~3단어, 동사로 끝나거나 "~하기".
- 기능 이름("등록") 대신 목적("신청서 내기", "채팅으로 물어보기").
- 같은 기능은 화면마다 같은 라벨.
- 마침표, 느낌표 없음.
- 주요 버튼과 닫기 버튼의 말투를 맞춘다("나중에 하기" / "지금 승인하기").
- 하단 버튼은 누르면 다음에 무슨 일이 일어나는지 말한다. 화면에서 이미 설명한 혜택이나 가치를 버튼에서 되풀이하지 않는다("최대 5만 원 받기" 대신 "본인 확인하고 받기"). 버튼 바로 위에 같은 말을 부풀린 안내 문구를 또 달지 않는다.
- 대화상자의 왼쪽 버튼은 언제나 "닫기". "취소"는 하던 일 자체가 취소되는 줄 알게 만든다.

## 제목

- 화면 제목은 그 화면의 할 일이나 질문. "신청 관리" 보다 "확인할 신청이 6개 있어요"가 낫다(관리 화면은 제목은 짧게, 요약 문장으로 보충).
- 제목을 그대로 되풀이하는 설명 문장을 붙이지 않는다.
- 제목에 마침표를 찍지 않는다.

## 숫자, 날짜, 시간

- 아라비아 숫자. "세 개" 대신 "3개".
- 날짜는 "11월 28일 금요일", 표 안에서는 "11.28". 연도는 올해가 아닐 때만.
- 시간은 "오후 3시", 표 안에서는 "15:00".
- 금액은 "12,000원". 큰 금액은 "1억 2,000만 원".

## 문장 부호

- 가운데 점(·)을 쓰지 않는다. 쉼표나 "와/과"로.
- 긴 대시(—)를 쓰지 않는다. 쉼표, 괄호, 문장 나누기로.
- 물결(~)은 범위(3~5일)에만.
- 따옴표 남발 금지.

## 마지막 확인

- 옵션 라벨에 "추천"을 썼다면 "추시"로 잘못 쓰지 않았는지 본다.
- 영어를 그대로 쓴 곳(Submit, Dashboard, Settings)이 없는지 본다. 사용자가 영어 화면을 원할 때만 예외.
- 같은 대상을 화면마다 다른 말로 부르지 않는지 본다("신청", "접수", "요청" 섞어 쓰기).
